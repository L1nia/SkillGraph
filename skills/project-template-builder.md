# Шаблон проекта: управляемые таблицы и Excel

Используй этот скилл для создания нового рабочего приложения, похожего по структуре и визуальному языку на задачи 1, 8, 10, 11, 12, 71 и 71.4. Пользователь задаёт параметры, загружает данные, работает с таблицей, фильтрами и колонками, получает информационные сообщения и выгружает результат в Excel.

Этот документ является **обязательным самодостаточным контрактом**, а не набором пожеланий. Промпт запуска сообщает только название, абсолютный путь и предметную задачу. Предметную область, подписи, API и колонки бери из задания пользователя, но все визуальные решения, архитектуру интерфейса, стек, обязательные файлы, порядок агентных этапов и критерии приёмки бери только из этого скилла.

## 1. Порядок источников истины

Разделяй предметную постановку и контракт реализации:

1. Системные ограничения среды и явные требования пользователя к **назначению экрана, бизнес-логике, полям, данным и API** определяют, что делает проект.
2. Этот скилл и его положительные изображения-референсы единолично определяют, **как проект устроен и выглядит**: композицию, размеры, состояния, цвета, типографику, стек, файлы, агентный процесс и приёмку.
3. Положительные изображения являются источником истины для наблюдаемого внешнего вида; текст скилла уточняет поведение и точные размеры. Анти-референсы определяют запрещённые варианты.
4. Существующий проект учитывается только для совместимости и не отменяет контракт скилла.

Если промпт запуска повторяет или пересказывает визуальные, архитектурные, технологические требования либо состав артефактов и это описание расходится со скиллом, **игнорируй конфликтующую часть промпта и следуй скиллу**. Не пытайся смешать два варианта и не проси пользователя выбрать между ними. Исключение — отдельный явный запрос пользователя именно на изменение `project-template-builder`; сначала обнови скилл, затем используй его новую версию.

Промпт не обязан перечислять header, таблицу, footer, цвета, размеры, hover/focus, библиотеку компонентов, README, Changelog, `AppFooter.tsx`, этапы Task Manager или критерии визуальной проверки. Их отсутствие в промпте не делает эти требования необязательными.

## 3. Обязательный стек

- React + TypeScript + Vite.
- `antd` — обязательная и единственная основная UI-библиотека.
- `@ant-design/icons` — основной источник иконок. Для трёх табличных кнопок, чекбоксов и сортировки допускается и требуется точное повторение задачи 8 через `@heroicons/react/24/outline`: `FunnelIcon`, `AdjustmentsVerticalIcon`, `ArrowDownTrayIcon`, `CheckIcon`. Не заменяй их похожими иконками Ant Design, если результат визуально отличается от референса.
- `ConfigProvider` с `theme.compactAlgorithm` и локалью `ru_RU`.
- CSS допускается для раскладки и точной подгонки под референс, но не для повторной реализации стандартных элементов Ant Design.

Запрещено заменять Ant Design произвольными самописными контролами или смешивать его с MUI, Bootstrap, Chakra, Mantine и другими UI-наборами. Исключения — перечисленные ниже примитивы задачи 8, для которых точный внешний вид важнее стандартного скина библиотеки: табличный toolbar, чекбоксы ячеек, стрелка сортировки и ручка изменения высоты.

### Обязательные примитивы задачи 8

Для header, tabular toolbar и двух меню не пересобирай внешний вид «по смыслу». Используй следующую структуру и классы как исходную реализацию. Разрешено адаптировать только предметные подписи и обработчики.

Header:

```tsx
<div className="bg-white p-4 border-b border-gray-200 rounded-lg">
  <Collapse
    bordered={false}
    className="omega-header-collapse"
    items={[{
      key: 'filters',
      label: <span className="text-sm font-semibold text-gray-900">Параметры фильтров</span>,
      extra: headerActions,
      children: <div className="flex flex-col gap-4">{filterRows}</div>,
    }]}
  />
</div>
```

```css
.omega-header-collapse.ant-collapse { background: transparent; }
.omega-header-collapse.ant-collapse > .ant-collapse-item { border: none; }
.omega-header-collapse .ant-collapse-header { align-items: center !important; padding: 0 !important; }
.omega-header-collapse .ant-collapse-content { border-top: none; }
.omega-header-collapse .ant-collapse-content-box { padding: 12px 0 0 !important; }
.omega-header-collapse .ant-collapse-expand-icon {
  color: rgb(75 85 99);
  font-weight: 400;
}
.omega-header-collapse .ant-collapse-arrow svg {
  width: 12px;
  height: 12px;
  stroke-width: 1.5;
}
```

Каждая строка полей использует `flex flex-wrap items-center gap-3`; метка — `w-48 shrink-0 text-sm font-medium text-gray-700`; основное поле — `w-80 shrink-0`; вертикальный промежуток между строками — `gap-4`. На широком экране запрещено заменять это на растянутый grid или `width: 100%`: именно фиксированные `12rem` и `20rem` формируют пропорции задачи 8.

Кнопка «Заполнить»:

```tsx
className="bg-blue-600 text-white px-4 py-2 rounded text-sm hover:bg-blue-700 focus:outline-none focus:ring-2 focus:ring-blue-500 disabled:bg-gray-400 disabled:cursor-not-allowed flex items-center gap-2"
```

Icon-only кнопки toolbar:

```tsx
className="p-2 rounded-md transition-colors bg-white border border-gray-300 text-gray-700 hover:bg-gray-50 hover:border-gray-400 focus:outline-none focus:ring-2 focus:ring-gray-400 focus:ring-offset-1"
```

Внутри используется ровно `w-5 h-5`; итоговый bounding box кнопки при стандартном `box-sizing: border-box` — `38×38px`. Не задавай `h-7`, `w-7`, `size="small"` или `padding: 4px`.

Кнопка XLS:

```tsx
className="bg-orange-600 hover:bg-orange-700 disabled:bg-gray-400 disabled:cursor-not-allowed text-white px-4 py-2 rounded-md text-sm font-medium transition-colors duration-200 flex items-center gap-2 min-w-[100px] justify-center"
```

Иконка `ArrowDownTrayIcon` имеет `w-4 h-4`; подпись — строго `XLS`. Не сокращай минимальную ширину и не используй маленький размер Ant Design Button.

Общая оболочка панелей «Фильтр» и «Колонки»:

```tsx
<div className="fixed inset-0 z-50 pointer-events-none">
  <div className="absolute inset-0 bg-black bg-opacity-10 pointer-events-auto" />
  <div
    className="absolute bg-white shadow-xl w-64 max-w-[calc(100vw-1rem)] flex flex-col pointer-events-auto rounded-lg overflow-hidden"
    style={{ top, right, maxHeight }}
  >
    {/* header, scrollable rows, footer */}
  </div>
</div>
```

Ширина панели — ровно `w-64` (`256px`). Header панели — `px-3 py-2 border-b border-gray-200 flex items-center justify-between`; заголовок — `text-[0.85rem] font-semibold text-purple-600 uppercase flex-1 text-center`; крестик — `XMarkIcon w-4 h-4`. Строка — `py-1.5 px-2.5`; switch — `h-4 w-7`, бегунок — `h-3 w-3`, включённое смещение — `translate-x-3`; подпись — `text-[0.75rem] text-gray-900 uppercase`. Для «Колонки» drag-handle — `Bars3Icon w-3.5 h-3.5 text-gray-400`, а не текстовые точки или чёрное многоточие.

Если эти классы конфликтуют с глобальной темой, исправляй локальный CSS, а не заменяй примитивы другой геометрией.

### Hover, focus и disabled — точный контракт задачи 8

Не объединяй состояния `hover` и `focus` и не добавляй собственные эффекты. В задаче 8 нет подъёма элемента, масштабирования, цветной тени, градиента или анимации геометрии при наведении. Переходы меняют только цвет фона, границы или текста.

#### Поля ввода

Обычные `input` и `textarea` в header используют:

```tsx
className="border border-gray-300 bg-white rounded px-3 py-1 text-sm focus:outline-none focus:ring-2 focus:ring-blue-500 disabled:bg-gray-100"
```

- default: белый фон, граница `gray-300` (`#d1d5db`), без тени;
- hover: внешний вид **не меняется** — фон остаётся белым, граница остаётся серой; запрещены голубая заливка, увеличение, подъём и `box-shadow`;
- focus: стандартный outline убирается и появляется только синий ring `2px` цвета `blue-500` (`#3b82f6`); размер и положение поля не меняются;
- disabled: фон `gray-100` (`#f3f4f6`), управляющие действия недоступны.

Для полей активных табличных фильтров используется тот же focus, но с `focus:ring-offset-1`. Поле выбора оператора дополнительно имеет `hover:bg-gray-50`. Эту реакцию не переносить на обычные текстовые поля header.

Пункты истории/автодополнения используют `hover:bg-blue-50`; строки основного меню фильтра и колонок — `hover:bg-gray-50`.

#### Основные и вторичные кнопки

Кнопка «Заполнить»:

```tsx
className="bg-blue-600 text-white px-4 py-2 rounded text-sm hover:bg-blue-700 focus:outline-none focus:ring-2 focus:ring-blue-500 disabled:bg-gray-400 disabled:cursor-not-allowed"
```

- hover: меняется только фон `#2563eb` → `#1d4ed8`;
- focus: ring `2px #3b82f6`, без смещения и изменения размера;
- disabled: серый фон `gray-400`, курсор `not-allowed`; hover не должен возвращать синий цвет.

Кнопки «Фильтр» и «Колонки»:

```tsx
className="p-2 rounded-md transition-colors bg-white border border-gray-300 text-gray-700 hover:bg-gray-50 hover:border-gray-400 focus:outline-none focus:ring-2 focus:ring-gray-400 focus:ring-offset-1"
```

- hover: фон `#f9fafb`, граница `#9ca3af`, иконка остаётся `gray-700`;
- focus: серый ring `2px` с offset `1px`;
- размеры `38×38px` и размер иконки `20×20px` не меняются ни в одном состоянии.

Кнопка XLS:

```tsx
className="bg-orange-600 hover:bg-orange-700 disabled:bg-gray-400 disabled:cursor-not-allowed text-white px-4 py-2 rounded-md text-sm font-medium transition-colors duration-200 min-w-[100px]"
```

- hover: меняется только фон `#ea580c` → `#c2410c`;
- disabled: `gray-400`, без оранжевого hover;
- ширина, высота, положение иконки и текста не меняются.

Кнопки шестерёнки/служебного действия в header: `bg-white border-gray-300 hover:bg-gray-50 focus:ring-2 focus:ring-gray-400`. Крестик в панелях: текст `gray-400`, при hover только `gray-600`, без круглой цветной подложки.

#### Элементы панелей и таблицы

- строка «Фильтр»/«Колонки»: `hover:bg-gray-50`;
- switch: цвет меняется только по состоянию checked; при focus — `ring-2 ring-blue-500 ring-offset-1`; hover не увеличивает switch;
- drag-handle колонок: `hover:bg-gray-200`, иконка остаётся `gray-400`; разрешена только смена курсора `grab` → `grabbing` при перетаскивании;
- «СБРОСИТЬ»: `text-purple-600 hover:text-purple-700 focus:ring-2 focus:ring-purple-500`;
- строки таблицы: `hover:bg-gray-50`; активная строка сохраняет свой активный фон и не должна мигать другим цветом;
- ручка высоты таблицы при hover расширяет серую центральную полоску и слегка подсвечивает hit-area; при drag полоска становится темнее и шире. Высота рабочей области меняется только во время drag.

#### Проверка интерактивных состояний

В `docs/reference-audit.md` добавь матрицу `default / hover / focus / disabled` минимум для обычного поля header, «Заполнить», «Фильтр», «Колонки» и XLS. Проверяй состояния реальным наведением и фокусом в браузере, а не чтением классов. Сделай отдельные скриншоты hover для одного поля и всех трёх типов кнопок.

Считать результат FAIL, если:

- поле при hover получает синюю/серую заливку, тень или меняет размер;
- focus-ring показывается уже при простом hover;
- кнопка при hover масштабируется, сдвигается или получает цветную тень;
- icon-only кнопки не меняют одновременно фон и границу;
- hover активен на disabled-кнопке;
- браузерный чёрный outline отображается одновременно с заданным ring.

Минимальная конфигурация темы:

    algorithm: theme.compactAlgorithm,
    token: {
      colorPrimary: '#2563eb',
      colorBgLayout: '#f3f4f6',
      colorBgContainer: '#ffffff',
      colorBorder: '#d1d5db',
      colorText: '#111827',
      colorTextSecondary: '#6b7280',

Допускается уточнять значения токенов после визуального сравнения, но итог должен быть ближе к референсу задачи 8, а не к стандартной теме Ant Design.

### Цветовой контракт

Цвета проверяются по положительным референсам и не заменяются приблизительной «корпоративной» палитрой:

- фон страницы: нейтральный серый `#f3f4f6`, без голубого оттенка;
- рабочие панели, таблица и footer: `#ffffff`;
- границы контролов: `#d1d5db`, разделители таблицы: `#e5e7eb`;
- основной текст: `#111827`, вторичный: `#6b7280`;
- шапка таблицы и строка встроенных фильтров: `#f9fafb`;
- выделенная/hover-строка: нейтральный `#f3f4f6`, не синяя карточка;
- primary и включённые переключатели: `#2563eb`;
- заголовок панели фильтра и действие «СБРОСИТЬ»: фиолетовый `#a855f7`;
- кнопка XLS: оранжевая `#ea580c` с белым текстом;
- вторичные кнопки «Заполнить»: серые, если референс не показывает их primary-состояние.

Запрещён page canvas `#eef3f8` и другие заметно голубые подложки. Не добавляй цветные тени, градиенты или заливку всей таблицы.

### Типографика интерфейса

Оригинал задачи 8 использует стандартный стек Tailwind `ui-sans-serif/system-ui`; на Windows фактическим шрифтом является **Segoe UI**. Не устанавливай Arial для экранного интерфейса.

- основной текст и подписи полей: Segoe UI/system-ui, 14 px, normal;
- заголовок «Параметры фильтров»: 14 px, semibold (600);
- заголовки рабочих секций: 18 px, semibold;
- заголовки таблицы и footer: 12 px;
- заголовки таблицы допускают uppercase, компактный `line-height: 1.2` и центрирование как на референсе;
- Excel остаётся отдельным контрактом и продолжает использовать Arial 10 pt внутри файла.

## 4. Обязательная композиция

Страница строится в таком порядке:

1. `QueryParametersPanel` — **это header приложения**, а не секция под отдельной шапкой. Он расположен первым, реализован как сворачиваемая белая панель/`Collapse`, содержит шеврон, заголовок «Параметры фильтров», предметные поля и кнопки «Заполнить». Справа в заголовке допускаются только действия из референса: настройки таблиц и закрытие. Если задача предоставляет текущего пользователя, подпись `Пользователь: …` находится в header этой панели или её summary.
2. `MessageRegion` — тонкая условная строка между header и таблицей. Она появляется только при наличии сообщения; в пустом состоянии не резервирует большую карточку или фиксированную высоту.
3. `DataSection` — **одна** белая рабочая секция: заголовок, кнопки фильтра, колонок и XLS, затем единственная основная таблица либо её компактный placeholder.
4. `AppFooter` — обязательный стандартизированный footer после основного содержимого.

По умолчанию шаблон создаёт **ровно одну обычную предметную таблицу и ровно один `DataSection`**. Это универсальная таблица текущего проекта, а не перенесённый из задачи 8 компонент `MlTable`, `KVTable`, `WarehouseTable` или `CMSTable`. Не добавляй вторую таблицу, `KVTable`, блок «Содержимое КВ», master-detail, второй placeholder или зависимую секцию только потому, что они встречались в задаче 8. На обзорном референсе задачи 8 вторая таблица является предметной частью исходного приложения и **не входит в шаблон**. Дополнительная таблица допустима только при прямом требовании пользователя.

Task Manager не должен создавать отдельный этап или компонент для второй таблицы. После загрузки визуальная проверка обязана подтвердить: в DOM находится один основной `<table>` и одна рабочая секция с табличным toolbar. Служебные таблицы, создаваемые Ant Design отдельно для header/body, также считаются отклонением, если из-за них меняется геометрия оригинала. Второй API-набор при необходимости отображай колонками, деталями или модальным окном, но не автоматически второй таблицей.

**Не создавай отдельный `AppHeader` с названием приложения, подзаголовком, пользователем или версией.** На референсе задачи 8 такого блока нет. Версии располагаются только в footer. Любая отдельная верхняя полоса вроде «Реестр записей / Рабочий шаблон…» считается блокирующим расхождением.

На широком экране композиция должна визуально соответствовать `project-template-task8-overview`. Адаптивность разрешает перенос строк, но не меняет порядок блоков.

### Геометрия страницы и пустых блоков

Используй фактический ритм задачи 8:

- корень: `min-h-screen bg-gray-100`;
- внутренняя область: `mx-auto w-full px-4 py-4` — по 16px от краёв;
- header и следующая рабочая область разделены `mt-4`; последовательные рабочие карточки используют `space-y-4`;
- пустая карточка таблицы: `bg-white rounded-lg shadow p-6`; padding строго 24px, а не 12–16px;
- заголовок пустой карточки: `text-lg font-semibold text-gray-900 mb-4`; пояснение: `text-gray-500`;
- не задавай пустой карточке произвольную фиксированную высоту: её высоту формируют `p-6`, заголовок, `mb-4` и строка пояснения;
- footer начинается после `mt-12` (48px) и использует `py-6` (24px). Не прижимай его непосредственно к карточке и не растягивай пустой контент искусственными `min-height`.

Если базовый шаблон содержит одну таблицу, показывай одну такую карточку. Дополнительную карточку не создавай, но геометрию единственной карточки не уплотняй.

Используй `Form`, `Input`, `InputNumber`, `Select`, `Button`, `Collapse` и `Space` из Ant Design. Для выбора сущности через отдельное окно оставляй компактную кнопку с троеточием рядом с полем.

### Header задачи 8

`QueryParametersPanel` повторяет фактический `FilterControls` задачи 8:

- внешний контейнер белый, с `padding: 16px`, нижней тонкой границей и радиусом около `8px`;
- внутри один `Collapse` без собственной рамки; в summary слева шеврон и текст «Параметры фильтров» 14px/600, справа — только кнопка настроек таблиц и кнопка закрытия 36×36;
- поля расположены не в отдельной продуктовой шапке, а внутри раскрытого header;
- стандартная строка использует метку `w-48` (192px), **каждое основное поле** — `w-80 shrink-0` (320px), промежуток `gap-3` (12px); допустим перенос строк на узком экране без изменения порядка;
- первая группа: одно предметное поле и собственная кнопка «Заполнить»;
- вторая группа: основное поле, дополнительное поле и отдельная кнопка «Заполнить»;
- не добавляй заголовок приложения, подзаголовок, пользователя или версию над этой панелью.

Header использует `font-family: ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`; на Windows это Segoe UI. Не подменяй его Arial, Roboto или браузерным serif. Заголовок — 14px/600, подписи — 14px/500, значения — 14px/400. В исходном `FilterControls` задачи 8 раскрытая область использует `.ant-collapse-content-box { padding: 12px 0 0 !important; }`: дополнительного горизонтального inset внутри content-box нет. Метки полей выравниваются по контентной границе `Collapse`; не добавляй к ним ещё 16px слева и справа.

Chevron раскрытия — тонкая штатная Ant Design стрелка 12×12px со stroke около 1.5 и обычным весом. Не используй жирный символ `>`, заполненный треугольник или текстовую стрелку. В раскрытом состоянии он плавно поворачивается вниз.

Все поля одного уровня должны иметь одинаковую внешнюю ширину и высоту. Для task8-подобного header используй единый класс:

```tsx
const QUERY_FIELD_CLASS =
  "box-border block w-80 min-h-[30px] shrink-0 border border-gray-300 rounded px-3 py-1 text-sm leading-5 focus:outline-none focus:ring-2 focus:ring-blue-500 disabled:bg-gray-100";
```

Wrapper textarea/select также обязан иметь `w-80 shrink-0`, а внутренний контрол — `w-full`. Не допускай, чтобы одно поле стало 144–200px из-за `flex: 1`, содержимого или соседней подписи. Во второй строке основное поле и поле «ДСЕ» имеют одинаковые 320px. На узком viewport все поля переходят на одинаковое `w-full max-w-80`, а не получают разные вычисленные ширины.

Обе кнопки «Заполнить» имеют размер около `100×36px`, синий фон `#2563eb`, белый текст 14px и радиус около `4px`. Во время запроса они показывают белый spinner и текст «Загрузка…», а также блокируются. Не делай их серыми по умолчанию: серое состояние используется только для `disabled`.

### Логика «Заполнить»

- Кнопка первой группы активна только при валидном значении её поля.
- Кнопка второй группы активна, если заполнено хотя бы одно из двух связанных полей.
- Перед запросом нормализуй ввод так же, как при blur; ошибку валидации показывай в `MessageRegion`.
- Повторный клик с теми же параметрами обязан принудительно перезагрузить таблицу, а не вернуть старый локальный результат.
- Во время любого запроса загрузки блокируй обе кнопки, чтобы ответы не перезаписали друг друга; устаревший ответ отменяй или игнорируй по request id.
- Успешный ответ заменяет данные единственной таблицы; не создаёт вторую секцию.
- Ошибка сохраняет предыдущие успешно загруженные данные и показывает повторяемое сообщение, если повтор безопасен.

### Настройки таблиц и закрытие приложения

Кнопка-шестерёнка в header — рабочий trigger, а не декоративная иконка:

- размер кнопки 36×36px, `Cog6ToothIcon` 20×20px;
- клик обязательно меняет open-state и открывает привязанную к кнопке панель; повторный клик, Escape, крестик и клик по overlay закрывают её;
- панель позиционируется через фактический `getBoundingClientRect()` trigger-кнопки, имеет `position: fixed`, `z-index: 50`, `w-80` (320px), белый фон, `shadow-xl`, радиус 8px и `max-height: calc(100vh - 100px)`;
- overlay — `fixed inset-0 bg-black/10`; панель не должна обрезаться `Collapse` или родителем с `overflow: hidden`;
- header панели: центрированный фиолетовый uppercase «НАСТРОЙКИ ТАБЛИЦ» и крестик справа;
- внутри ровно две карточки: «По умолчанию» и «Пользовательская»; активная отмечена зелёной `CheckIcon` 16×16px сразу после названия;
- каждая карточка имеет `border border-gray-200 rounded-lg p-3`; между карточками `space-y-3`; запрещены описательные абзацы вроде «Исходные видимость…» или «Сохранённых настроек пока нет…»;
- внутри «По умолчанию» находится собственная полноширинная синяя кнопка с `ArrowPathIcon` и подписью «Загрузить»;
- внутри «Пользовательская» находятся собственная синяя «Загрузить» и зелёная «Сохранить текущие настройки» с `CheckIcon`, вертикальный gap 8px;
- запрещено выносить общие кнопки «Загрузить»/«Сохранить» ниже обеих карточек и окрашивать сохранение синим;
- кнопки: высота около 36px, `px-4 py-2 text-sm`; загрузка `bg-blue-600 hover:bg-blue-700`, сохранение `bg-green-600 hover:bg-green-700`;
- если сохранённых пользовательских настроек ещё нет, панель всё равно открывается; состояние выражается доступностью действий и active-check, без дополнительного описательного абзаца. Нельзя оставлять кнопку-шестерёнку без реакции.

Эталон — `project-template-task8-settings-correct`; `project-template-incorrect-settings-card` является блокирующим анти-результатом.

Кнопка «Закрыть» закрывает **всё приложение**, а не скрывает `QueryParametersPanel`, не удаляет header из DOM и не переключает локальный флаг видимости. Передай обработчик из корневого `App`. При несохранённых данных/настройках сначала покажи подтверждение «сохранить / закрыть без сохранения / отмена». После подтверждения используй отдельный `closeApplication()`:

1. host API `window.Omega.close()` или `window.Omega.closeWindow()`, если он доступен;
2. сообщение контейнеру `postMessage("close", "*")` и `postMessage({ action: "close" }, "*")`;
3. `window.close()`;
4. `history.back()` только как последний browser fallback.

Добавь тест, что клик вызывает корневой close-flow, а не скрывает header.

### Дата и диапазон дат

В исходном интерфейсе задачи 8 используется нативный элемент `<input type="date">`, а не `DatePicker`/`RangePicker`. В React + Ant Design используй `<Input type="date">` либо нативный `input type="date"`, если требуется точное совпадение размеров. Для диапазона выводи два поля `type="date"`, разделённые обычным дефисом; значения храни в ISO `YYYY-MM-DD`. Не подменяй их текстовыми полями с placeholder и не создавай собственный календарь. Системная иконка календаря и локализованный вид даты принадлежат браузеру.

- Обязательные поля помечай звёздочкой.
- Кнопка загрузки остаётся основной синей кнопкой.
- До валидной загрузки экспорт отключён.
- Ошибка валидации показывается в `MessageRegion`, а не случайным toast вместо блока.
- Предметные подписи и набор полей бери из запроса; не копируй тестовые значения референса.

## 7. Таблица, фильтр и колонки

Для единственной основной таблицы используй обычный семантический `<table>` с отдельными компонентами `colgroup`, `thead` и `tbody`, как в `MlTable` задачи 8. Ant Design остаётся обязательным для приложения и окружающих контролов, но стандартный `Table` Ant Design **не является эталоном**: он создаёт собственную геометрию header/body, другие scrollbars и дополнительные внутренние таблицы. Допускай `Table` Ant Design только если визуальная проверка доказывает равенство исходному `<table>`; иначе используй нативную табличную композицию. Панель над таблицей содержит:

- icon-only кнопку «Фильтр» 38×38px с `FunnelIcon` 20×20px;
- icon-only кнопку «Колонки» 38×38px с `AdjustmentsVerticalIcon` 20×20px;
- оранжевую кнопку `XLS` около 100×36px с `ArrowDownTrayIcon` 16×16px и подписью `XLS`;
- расстояние между кнопками около `12px`; все три выровнены по центру одной строки.

Кнопки «Фильтр» и «Колонки»: белый фон, рамка `#d1d5db`, радиус около `6px`, текст/иконка `#374151`, hover `#f9fafb`, focus-ring серый. `XLS`: `#ea580c`, hover темнее, белая иконка и текст, `font-weight: 500`; во время экспорта — spinner и `Экспорт…`. Не используй текст «Excel» и не растягивай кнопку шире референса.

### Полоса активных фильтров

После включения хотя бы одного фильтра вставляй между toolbar и таблицей отдельную полноширинную полосу:

<div className="px-6 py-3 border-b border-gray-200 bg-gray-50 overflow-x-auto w-full">

    <div className="flex flex-wrap gap-4 items-center w-full">{/* active fields */}</div>

Каждый фильтр состоит из отдельной подписи `text-sm text-gray-600 whitespace-nowrap`, затем контрола и отдельной кнопки очистки `XMarkIcon 20×20px`. Не показывай двоеточие как часть placeholder. Полоса появляется только при `activeFilters.size > 0` и исчезает после сброса последнего фильтра.

- Scrollbar задачи 8 — часть визуального контракта: для WebKit ширина/высота `20px`, track `#cbd5e1` с рамкой `#94a3b8`, thumb `#334155` с радиусом `10px` и внутренней рамкой `3px solid #cbd5e1`; hover thumb `#1e293b`, active `#0f172a`. Не подменяй его тонким нативным scrollbar стандартной Ant Table.
- Шапка закреплена. Для логических групп используй `columns.children`/`colSpan`/`rowSpan`: эталон содержит многоуровневые заголовки, а не одну плоскую строку.
- Заголовки 12px, uppercase, цвет `#6b7280`, `line-height: 1.2`, центрирование и перенос строк. Высота шапки определяется группами и не сжимается в одну строку.
- Строки данных имеют высоту примерно `36–40px`, ячейки — 14px. Числа выравнивай вправо или по центру согласно референсу.
- Первые идентифицирующие колонки закрепляй слева через `fixed: 'left'`/sticky offsets; край закреплённой области отделяй тонкой тенью.
- До первой успешной загрузки показывай исходное пустое состояние задачи 8: белую карточку `rounded-lg shadow p-6` с заголовком и пояснением, **без** toolbar и шапки. После успешной загрузки карточка заменяется полноценной рабочей таблицей. При нулевом результате уже выполненного запроса допускается сохранить toolbar/шапку и показать «данные не найдены».
- Заголовки, границы, плотность строк, пустое состояние и выравнивание сверяй с референсами `project-template-task8-populated-table` и `project-template-task8-empty-table`.
- Значения из скриншотов не копируй: используй пустое состояние или данные предметной области.
- Длинные значения сокращай с tooltip; числа выравнивай вправо, даты — единообразно.
- При ошибке загрузки внутри секции отображай красное пояснение, почему таблица не заполнена.

### Checkbox'ы в ячейках

Повторяй исходный контрол задачи 8, а не стандартный крупный Ant Design checkbox:

- внешний размер `16×16px`, белый фон, радиус около `4px`, рамка `2px`;
- активный неотмеченный: тёмная рамка `#111827`; disabled — серая `#9ca3af`;
- отмеченный: белый фон, тёмная рамка и зелёная `CheckIcon` размером около `12×12px`, `strokeWidth={3}`; не заливай весь квадрат синим;
- клик по checkbox не должен выбирать строку: `stopPropagation()`; используй `role="checkbox"`, `aria-checked` и понятный `aria-label`;
- один и тот же компонент и состояния используются во всей таблице; не смешивай native checkbox, radio и разные цветовые схемы без доменной причины.

### Изменение высоты таблицы

Внизу карточки таблицы используй **перетаскиваемую горизонтальную ручку**, один в один как `TableResizeHandle.tsx` задачи 8. Это не `input[type=range]`, не круглый thumb, не символ `...` и не декоративный текст.

```tsx
<div
  role="separator"
  aria-orientation="horizontal"
  aria-label="Изменить высоту таблицы"
  onMouseDown={onResizeStart}
  className={`group relative z-10 flex h-3 flex-shrink-0 cursor-ns-resize items-center justify-center transition-colors ${
    isResizing ? "bg-gray-500/10" : "hover:bg-gray-500/5"
  }`}
>
  <div
    className={`absolute left-1/2 top-1/2 -translate-x-1/2 -translate-y-1/2 rounded-full transition-all duration-200 ${
      isResizing
        ? "h-1.5 w-24 bg-gray-700"
        : "h-1 w-14 bg-gray-500 group-hover:h-[5px] group-hover:w-20 group-hover:bg-gray-600"
    }`}
  />
  <div className="pointer-events-none relative flex items-center gap-1" aria-hidden="true">
    <span className="block h-1 w-1 rounded-full bg-gray-500 group-hover:bg-gray-600" />
    <span className="block h-1 w-1 rounded-full bg-gray-500 group-hover:bg-gray-600" />
    <span className="block h-1 w-1 rounded-full bg-gray-500 group-hover:bg-gray-600" />
  </div>
</div>
```

- hit-area имеет высоту `12px`, располагается сразу под scroll-контейнером таблицы и входит в ту же белую карточку;
- default: центральная полоска `56×4px`, `#6b7280`, поверх неё три точки `4×4px`;
- hover: полоска примерно `80×5px`, `#4b5563`, фон hit-area `gray-500/5`;
- active drag: полоска `96×6px`, `#374151`, фон hit-area `gray-500/10`;
- курсор `ns-resize`; на `mousedown` сохрани начальную Y-координату и высоту, на `mousemove` меняй только высоту scroll-контейнера, на `mouseup` очисти listeners;
- ограничивай высоту диапазоном проекта (обычно 150–800px и доступной высотой viewport), не меняй ширины колонок;
- итоговую высоту сохраняй в том же snapshot настроек, что видимость, порядок и ширины колонок;
- три точки являются внутренним индикатором поверх полоски, но **не заменяют саму полоску** и не выводятся как текстовое многоточие.

Анти-результат: отдельная белая полоса высотой 20px с `input[type=range]`, круглым thumb и коротким track. Именно такой вариант был создан в тестовом проекте и не соответствует исходному `TableResizeHandle` задачи 8.

### Стрелочная сортировка

- Для сортируемой колонки показывай текстовую стрелку `↑`; при активной сортировке по убыванию — `↓`. Не заменяй их треугольниками или иконками другой формы.
- Стрелка находится в собственной кнопке размером 20×20px, цвет `#21a865`, `font-size: 20px`, `font-weight: 700`, без рамки и фона. Она скрыта через `opacity: 0` по умолчанию и видна только при hover соответствующего header, `:focus-visible` или когда колонка уже отсортирована. Запрещено одновременно показывать стрелки во всех заголовках.
- Стрелка размещается рядом с правой частью текста внутри `.column-header-content`, а справа остаётся 16px gutter для resize-handle; она не меняет центрирование заголовка.
- Клик вызывает сортировку и делает `preventDefault()` + `stopPropagation()`, чтобы не запускать resize или выбор колонки.
- При сжатии колонки измеряй пересечение стрелки с текстом через `ResizeObserver`; если текст перекрывается или обрезается, добавляй локальную подложку/тень под стрелкой, не скрывая её.
- Текущее направление сохраняй в snapshot настроек и применяй к уже загруженным строкам без повторного API-запроса, если серверная сортировка явно не требуется.

### Изменение ширины колонок

Каждая изменяемая колонка получает отдельный `ColumnResizeHandle` по правому краю header-cell:

```tsx
<span
  role="separator"
  aria-orientation="vertical"
  aria-label="Изменить ширину колонки"
  className={`column-resize-handle${active ? " is-active" : ""}`}
  onPointerDown={handlePointerDown}
/>
```

Обязательная геометрия и пунктир:

```css
.column-resize-handle {
  position: absolute;
  top: 0;
  right: 0;
  z-index: 6;
  width: 16px;
  height: 100%;
  cursor: col-resize;
  touch-action: none;
  user-select: none;
}
.column-resize-handle::after {
  content: "";
  position: absolute;
  top: 0;
  right: 0;
  bottom: 0;
  width: calc(4px - 1pt);
  background: transparent;
}
.column-resize-handle:hover::after,
.column-resize-handle.is-active::after {
  background: repeating-linear-gradient(
    to bottom,
    #374151 0,
    #374151 6px,
    transparent 6px,
    transparent 11px
  );
}
```

Header-cell должна иметь `position: relative` и `overflow: visible`. Пунктирная линия видна только при hover или активном drag; это вертикальные штрихи 6px с промежутком 5px, а не сплошная граница и не символы `⋮`.

На `pointerdown` сохрани `clientX` и исходную ширину, затем обновляй ширину по `pointermove` до `pointerup`. Используй pointer capture или document listeners с обязательной очисткой. Ограничивай ширину `minWidth`/разумным `maxWidth`, не позволяй отрицательные значения и не запускай сортировку: `preventDefault()` + `stopPropagation()`. Новую ширину сохраняй в snapshot настроек таблицы и восстанавливай при загрузке.

## 10. Стандартный AppFooter.tsx

Используй единый публичный контракт:

```tsx
export type AppFooterProps = {
  frontendVersion: string;
  backendVersion: string;
  lastModifiedDate: string;
};

export function AppFooter({
  frontendVersion,
  backendVersion,
  lastModifiedDate,
}: AppFooterProps) {
  return (
    <footer className="app-footer" aria-label="Информация о сборке">
      <span>
        Фронт: {frontendVersion} | Бэк: {backendVersion} | Дата: {lastModifiedDate}
      </span>
    </footer>
  );
}
```

Обязательный стиль:

```css
.app-footer {
  margin-top: 48px;
  padding: 24px 16px;
  border-top: 1px solid #e5e7eb;
  background: #fff;
  color: #4b5563;
  font: 12px/1.2 ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
  text-align: center;
}
```

Это эквивалент исходных классов задачи 8 `mt-12 py-6 border-t border-gray-200 bg-white` и `text-center text-xs text-gray-600`. Не задавай footer собственную минимальную высоту, голубую границу `#cbd7e3` или сине-серый текст `#52657a`: такие значения были в тестовом проекте, но отсутствуют в исходном `AppFooter` задачи 8.

Подпись и разделители обязательны **буквально в формате** `Фронт: … | Бэк: … | Дата: …`. `Дата` означает дату последних изменений фронтенда, а не текущую дату запуска и не произвольную дату сборки. Все три значения поступают из конфигурации/окружения; при временной недоступности версии бэка показывай `Бэк: —`, не удаляй сегмент. На узком экране разрешён перенос строки с сохранением порядка и разделителей.

Файл `src/components/AppFooter.tsx` создаётся всегда, даже если footer или обязательные артефакты не перечислены в промпте. Не определяй footer inline в `App.tsx` и не заменяй его компонентом с другим публичным контрактом.

## 11. Контракт для Task Manager и агентной цепочки
