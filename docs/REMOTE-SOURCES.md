# Удалённые источники SkillGraph

В реестр `skillgraph/registry-v2` добавлена коллекция `sources`. Она хранит
описание подключения, но не секреты:

- `type`: `git` или `http-json`;
- `provider`: `github`, `gitlab` или `http`;
- `endpoint`: HTTPS-ссылка на репозиторий либо API сервера;
- `branch` и `path`: необязательные ветка и папка со скиллами;
- `skillIds`: ID, прочитанные при последнем обновлении;
- `status`, `lastSyncAt` и `lastError`: состояние чтения.

## Контракт будущего адаптера

Desktop-адаптер читает дерево публичного или приватного репозитория через
официальные REST API GitHub/GitLab. Репозиторий не клонируется и файлы не
создаются в папке приложения. Подходящие `SKILL.md`, `*.skill.md` и реестры
`registry.json`/`skills.json` загружаются в память, нормализуются и попадают в
общий граф. У записи скилла сохраняется `origin` со ссылкой на источник.

HTTP/JSON-адаптер выполняет `GET` по HTTPS и принимает один из форматов:

- полный `skillgraph/registry-v2` или `registry-v1`;
- JSON-массив скиллов либо объект с массивом `skills`;
- объект `{ "items": [{ "name", "path", "content" }] }`;
- одиночный Markdown-документ скилла.

Для закрытого API можно передать Bearer token на время одного запроса.

Access token можно ввести для одного чтения приватного репозитория. Он не
попадает в `registry.json`. Повторное обновление публичного источника выполняется
без токена; для приватного токен запрашивается снова. Ограничения: не более 250
файлов, 1,5 МБ на файл и 12 МБ суммарно.

## Далее

Для будущих версий остаются OAuth/Windows Credential Manager, предварительный
просмотр конфликтов и адаптеры нереляционных баз. Локальные ZIP-архивы также
продолжают импортироваться.
